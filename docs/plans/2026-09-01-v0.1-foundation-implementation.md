# Agent Teamworks V0.1 Foundation Implementation Plan

**Goal:** Publish a reusable, reviewable foundation for persistent multi-agent project teams.

**Non-goals:** Hosted orchestration, a dashboard, complex CLI tooling, and project-specific private state.

**Architecture:** Keep the framework as the source of truth; expose machine-readable records through schemas, practical behavior through protocols and examples, and a thin Codex Skill as one adapter.

## Spec Link

- [`docs/specs/2026-09-01-v0.1-foundation.md`](../specs/2026-09-01-v0.1-foundation.md)

## Global Constraints

- **Provided:** The public project is named Agent Teamworks and lives at `bells0/agent-teamworks`.
- **Provided:** Roles persist across a large project and collaborate as one established team.
- **Provided:** Work must still be decomposed according to the actual task and its dependencies.
- **Provided:** Development uses a feature branch, pull request, owner approval, merge, and safe branch cleanup.
- **Proposed:** JSON is the canonical V0.1 record format because it is directly compatible with JSON Schema and requires no YAML-specific runtime.
- **Proposed:** The public example is fictionalized to avoid publishing private project state.

## Acceptance Evidence

### Task 1: Define the reusable team operating model

**Outcome**

A reader can form and operate the smallest justified persistent team, route new work, replace an agent without losing role continuity, and close the team deliberately.

**Files**

- Create: `framework/operating-model.md` — lifecycle and invariants.
- Create: `roles/*.md` — stable responsibility contracts.
- Create: `protocols/*.md` — formation, routing, handoff, review, acceptance, and escalation behavior.

**Interfaces**

- Consumes: Accepted V0.1 core semantics and authority boundary.
- Produces: Human-readable rules implemented by schemas and adapters.

**Implementation notes**

- Keep roles configurable; examples are starting points, not a mandatory roster.
- Separate persistent logical roles from replaceable agent bindings.
- Route decomposed work into roles rather than recreating a team for each work item.

**Evidence**

- Observe: Every operating invariant maps to at least one lifecycle or protocol section.

### Task 2: Make the method durable and testable

**Outcome**

Projects can store team state as validated records, and a sanitized example demonstrates the complete continuity path.

**Files**

- Create: `schemas/*.schema.json` — Team, Role, Work Item, Handoff, and Decision contracts.
- Create: `examples/commerce-project/**` — fictionalized team instance.
- Create: `scripts/validate.py` and `tests/**` — schema, record, and repository consistency checks.
- Create: `evals/scenarios.md` — forward-evaluation cases and failure conditions.

**Interfaces**

- Consumes: Task 1 terminology and lifecycle states.
- Produces: Versioned record contracts and observable validation evidence.

**Implementation notes**

- Keep validation local and deterministic.
- Do not include private URLs, current private-project state, credentials, or user identifiers.

**Evidence**

- Run: `python3 scripts/validate.py`
- Observe: All schemas parse; examples validate and cross-references resolve.

### Task 3: Package the framework for adoption

**Outcome**

Codex and human contributors can discover, adopt, and evolve Agent Teamworks without copying the entire method into each prompt.

**Files**

- Create: `skills/agent-teamworks/**` — thin Codex entry point and metadata.
- Create: `adapters/codex/README.md` — runtime mapping and limitations.
- Modify: `README.md` — positioning, adoption, structure, and lifecycle overview.
- Create: `CONTRIBUTING.md`, `.github/pull_request_template.md`, and `.github/workflows/validate.yml` — traceable contribution path.

**Interfaces**

- Consumes: Tasks 1 and 2 as framework source of truth.
- Produces: Discoverable Skill routing and repository delivery workflow.

**Implementation notes**

- The Skill routes to framework sources; it does not duplicate them.
- Keep implicit discovery enabled and preserve authorization boundaries.

**Evidence**
